# Ключевые решения

Формат: дата — решение — причина — альтернатива и почему отклонена.

| Дата | Решение | Причина | Отклонённая альтернатива |
|---|---|---|---|
| 2026-09-09 | Текст/кодинг: Ollama в Docker + Open WebUI | Простейшее сопровождение: Ollama сам качает модели и управляет гибридным offload GPU/RAM (num_gpu) | llama.cpp вручную — больше контроля, но ручная загрузка/конфиг; LocalAI — монолит, менее прозрачен |
| 2026-09-09 | Изображения: ComfyUI, звук: AudioCraft — отдельными Docker-сервисами | Каждый стек заточен под свой тип моделей; проще отлаживать и обновлять по отдельности | Один универсальный backend (LocalAI) — хуже качество/удобство по каждому типу |
| 2026-09-09 | Апгрейд RAM вынесен в отдельный этап 6 (до 64–128 ГБ) | Сейчас 23,5 ГБ: 70B Q4 (~40 ГБ) в гибрид не влезет; без апгрейда реалистичны модели ≤20B | Сразу грузить 70B через сильное квантование Q2 — неприемлемая потеря качества |
| 2026-09-10 | Русскую модель не выделяем: русский покрывает qwen2.5:7b | В библиотеке Ollama нет русскоязычных моделей (vikhr/saiga/t-lite — 404); qwen2.5 хорошо держит русский (eval пройден) | Импорт GGUF с Hugging Face — рабочий, но лишний шаг сопровождения; оставлен запасным путём |
| 2026-09-10 | Приоритет TTS-озвучки над музыкой и частью старого плана | Пользователь: главный сценарий — автоматическая озвучка текстов/книг; AudioCraft (музыка) перенесён в backlog | Оставить музыку этапом 5 — не соответствует реальной потребности |
| 2026-09-10 | TTS: openedai-speech (XTTS v2) как OpenAI-совместимый endpoint | XTTS v2 поддерживает русский, ~2–3 ГБ VRAM, штатная интеграция с Open WebUI (кнопка озвучки); Silero/Piper — проще, но нет штатной интеграции с WebUI | Silero (CPU) — качество ниже XTTS для длинной озвучки; F5-TTS — тяжелее в сопровождении |
| 2026-09-10 | Мульти-юзер: signup открыт, DEFAULT_USER_ROLE=pending | Разные пользователи стенда; регистрация по одобрению админа разделяет чаты и запросы | Закрытый signup с ручным созданием учёток — больше ручной работы админа |
| 2026-09-10 | Open WebUI 0.11: конфиг хранится в sqlite и перекрывает env | Env ENABLE_SIGNUP применились только прямой правкой таблицы config (ключи ui.enable_signup, ui.default_user_role) | Пересоздание volume — потеряли бы все данные; env WEBUI_* работают только при первом старте |
| 2026-09-10 | Постоянное правило: новые задачи → через grill-me перед исполнением | Пользователь: так все новые задачи получают стресс-тест плана до начала работ; уточнения идут без grill-me | Сразу исполнять новые задачи — потеря шага проектирования и выявления скрытых решений |
| 2026-09-10 | 72B на этом стенде — только фоновые задачи | Скорость 0.8 ток/с при любом num_gpu: узкое место — CPU-слои и пропускная способность DDR4, не GPU; интерактив — 14B/32B | Пытаться ускорить 72B большим offload — тупик (VRAM 12 ГБ всё равно мала, 19 слоёв = OOM) |
| 2026-09-10 | ComfyUI: образ obeliks/comfyui:latest-cu126; модель RealVisXL V5.0 fp16 | Образ обновляется ежедневно (свежий ComfyUI), cu126 подходит под драйвер 595; RealVisXL — сильный фотореализм на SDXL, 6.9 ГБ влезает в 12 ГБ VRAM с запасом (30 сек/1024²) | Официальный comfyui/base — устарел (2024); FLUX — >12 ГБ VRAM, OOM на 3060 |
| 2026-09-11 | LLM-стенд свёрнут, сервер очищен под одноузловой Kubernetes | Пользователь: сервер нужен как k8s-площадка для экспериментов; выбрана очистка существующей ОС, не переустановка через Proxmox | Чистая установка Ubuntu — потеряла бы уже настроенный GPU-драйвер и nvidia-container-toolkit без выгоды |
| 2026-09-11 | k8s: k3s (stable, v1.36.4), не microk8s/kubeadm | Минимальный оверхед (~1–2 ГБ RAM), нативный containerd, автодетект GPU-рантайма, один бинарь через systemd | kubeadm — тяжелее (etcd/apiserver отдельно); microk8s — snap-обёртка, менее прозрачна |
| 2026-09-11 | GPU в k8s: device plugin + RuntimeClass nvidia; k3s сам прописывает nvidia-runtime в containerd | k3s v1.36 авто-добавляет рантайм при наличии nvidia-container-runtime; контейнеры с GPU требуют runtimeClassName: nvidia (иначе нет CUDA-библиотек); дефолтный рантайм не трогаем — системные поды остаются на runc | default_runtime_name=nvidia для всех подов — лишняя инъекция библиотек в каждый контейнер |
| 2026-09-11 | Docker engine на хосте оставлен после перехода на k3s | Нужен для сборки образов (docker build) перед загрузкой в containerd k3s; весит ~0.5 ГБ | Удаление docker — экономия мизерная, а сборку образов пришлось бы решать заново (buildkit/kaniko) |
